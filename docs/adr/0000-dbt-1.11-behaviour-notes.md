# dbt 1.11 behaviour notes

Spike on 24 Nov 2026 against dbt 1.11.11 and dbt-duckdb 1.9.6. This is a lab note, not a decision. The decisions that use it are ADR 0001, ADR 0002, and ADR 0003.

The spike used a copy of the project. Nothing in that copy was merged.

## Groups and access

`groups:` in `dbt_project.yml` is rejected: `Additional properties are not allowed ('groups' was unexpected)`. Group definitions are a properties file, `models/_groups.yml`.

`access: private` plus `group: revenue` on staging fails the parse when `dim_account` is in another group:

```text
Node model.arr_semantic_layer_lab.dim_account attempted to reference node
model.arr_semantic_layer_lab.stg_salesforce__accounts, which is not allowed
because the referenced node is private to the 'revenue' group.
```

The same error fires for a singular test until `data_tests: +group: revenue` is set. A project-level `analyses: +group` did not assign the group. `{{ config(group='revenue') }}` in the analysis file did. After those two assignments, `dbt build` completed: `PASS=147`. Unit tests referenced private models successfully. They have no `group` attribute; their `given` inputs are not rejected the way a model `ref` is.

`marts.core: +group: platform` applies to `dim_date` and `metricflow_time_spine`. A model property `group: revenue` on `dim_account` overrides the directory.

On the Snowflake parse, top-level `access`, `group`, and column `meta` in a properties file warn as `PropertyMovedToConfigDeprecation` (16 occurrences). Putting them under `config` removes the warning. The manifest still exposes `access`, `group`, and `columns.*.meta` to the gate.

## Contract breaking changes

Compared with `dbt build --select state:modified --state <prior manifest>`.

Removing `movement_amount` from the unversioned contracted model warns and does not stop the build. The event is `UnversionedBreakingChange` (I071):

```text
Breaking change to contracted, unversioned model fct_arr_movement
  - Columns were removed:
    - movement_amount
```

Adding `versions: [{v: 1, defined_in: fct_arr_movement}]` changes the node id to `model.arr_semantic_layer_lab.fct_arr_movement.v1`. Removing `movement_amount` from that version, against a state manifest that still has the column, fails the build:

```text
Breaking change to contract Error in model fct_arr_movement
  While comparing to previous project state, dbt detected a breaking change
  to an enforced contract.
    - Columns were removed:
      - movement_amount
```

`dbt parse --state` did not raise that error. The check runs on build, which is the state-comparison step CI already has. An unversioned contract break will not fail CI by itself. A versioned one will, once the prior manifest contains the version.

## Deprecation

`deprecation_date: 2020-01-01` on `fct_arr_snapshot` warns, and names downstream **models** only:

```text
Model fct_arr_snapshot has passed its deprecation date of 2020-01-01T00:00:00+00:00.
While compiling 'dq_arr__freshness': Found a reference to fct_arr_snapshot, which was deprecated on '2020-01-01T00:00:00+00:00'.
While compiling 'fct_arr_movement': Found a reference to fct_arr_snapshot, which was deprecated on '2020-01-01T00:00:00+00:00'.
```

Tests, analyses, and semantic models are not named. A versioned model warns as `fct_arr_movement.v1`. The warning is not an error.

## Unit tests on a versioned model

Parsing fails as soon as `fct_arr_movement` is versioned, before any unit test runs:

```text
Unit test 'fct_arr_movement_classifies_key_balance_transitions' references a
model that does not exist: model.arr_semantic_layer_lab.fct_arr_movement
```

The unit test stores the unversioned id while the model is still unversioned, and the later version pass does not rewrite it. Setting the unit test's `model` field to `fct_arr_movement v1` then fails with `Unable to find model`. A versioned mart in this dbt version needs a unit-test approach that is checked again before it is trusted. The existing unit tests stay on unversioned models.
